# 震源検出機能 要件定義（MeteoQuake-KyoshinViewer）

参考: [揺れ検知から震央を検出してみる｜ことほ](https://note.com/kotoho7/n/n59e423877b1b)

## 1. 目的

緊急地震速報（予報）が発表されない規模の地震（おおむねM3.5未満、最大予測震度3未満）でも、
強震モニタ／S-netのリアルタイム観測点データから揺れの広がり方だけを手がかりに、
**震源（緯度・経度・深さ・発生時刻）をアプリ内で推定して表示する**。

前提として、震度分布は震央を中心にほぼ同心円状に広がる（P波・S波が概ね一定速度で伝播するため）
という性質を利用する。参考記事のGeiger法（反復法）ベースの自己流アルゴリズムを踏襲しつつ、
本アプリの既存コード資産（[[shakeDetection.ts]] の検知エンジン、[[shakeTestSimulation.ts]] の
走時モデル）に合わせて簡略化する。

## 2. 全体方針

- 気象庁のJMA2001走時表は使わず、**shakeTestSimulation.ts と同じ固定P/S波速度モデル**
  （P波6.8km/s・S波3.9km/s、震源距離 = √(震央距離² + 深さ²)）を走時計算に流用する。
  → 走時テスト用シミュレーターと震源推定ロジックで前提となる物理モデルを一致させ、
    シミュレーションで動作検証しやすくする。
- 使用するデータは**検知時刻のみ**（記事の本編アルゴリズム相当）。振幅・最大PGV・
  B-Δ法・主成分分析による方位（記事「おまけ」のIPF法相当）は使わない＝**フェーズ2以降**。
- 震源推定は [[shakeDetection.ts]] が生成する「揺れ検知イベント」に対して、
  **イベント単位で**走らせる（イベントに属する観測点＝揺れ検知済み観測点の集合として扱う）。

## 3. 前提として必要なデータ（既存コードへの追加が必要）

現状の `ShakeDetectionEngine` はイベントに `pointIds` を持つが、**観測点ごとの実際の検知時刻**
（tick単位ではなく実時刻 `now`）を保持していない可能性が高い。震源推定には必須のため：

- イベントの各所属観測点について `firstDetectedAt`（その観測点が最初にこのイベントに
  加わった実時刻・ms）を記録・保持する。
- 観測点マスタ（`realtimeStations` 相当）の `lat`/`lon` は既存のものをそのまま利用可能。

## 4. アルゴリズム仕様

### 4.1 仮の震源を決める

- 対象イベントの中で**最初に検知した観測点**の位置を仮震源の緯度・経度とする
  （記事同様、小数第2位で丸め）。
- 深さ初期値: 10km。
- 発生時刻初期値: 最初の検知時刻 − 2秒。

### 4.2 誤差レベルの計算

イベントに属する（＝揺れ検知済みの）全観測点について:

1. 仮震源からの震央距離・震源距離を計算。
2. `shakeTestSimulation.ts` の P/S波速度モデルで走時を計算（検知がP波由来かS波由来かは
   区別せずP波走時を使用する＝記事と同様の簡略化。フェーズ2でS波判定を検討）。
3. 各観測点の「検知時刻 − 走時」＝推定発生時刻を求める。
4. 重み = 最初に検知した観測点の震央距離 ÷ 自点の震央距離（震央距離50km以内は重み1に固定）。
5. 全観測点の推定発生時刻の重み付き分散を「誤差レベル」とする
   （＝ Σ 重み×(推定発生時刻 − 平均発生時刻)²）。

### 4.3 着未着法（未検知観測点によるペナルティ）

揺れ検知から3秒以内、または検知数が30点未満の間のみ適用:

1. 検知済み観測点の最大震央距離 + 30km以内にある**未検知**の観測点を対象に、震央距離・走時を計算。
2. 検知済み観測点の平均発生時刻 + 走時 ＝ 到達予定時刻を算出。
3. 到達予定時刻 < 現在時刻（＝計算上は届いているはずなのに未検知）の観測点1点につき、
   誤差レベルに +1 する。

### 4.4 仮震源の反復移動（Geiger法簡略版）

以下を順に実行し、都度「誤差レベルが下がらなくなるまで候補へ移動」を繰り返す：

1. 緯度・経度 ±0.5度（深さ固定）の4候補
2. 緯度・経度 ±0.1度（深さ固定）の4候補
3. 緯度・経度 ±0.1度・深さ ±50km の6候補
4. 緯度・経度 ±0.1度・深さ ±10km の6候補

各ステップで、仮震源より誤差レベルが低い候補があればそこへ移動し、無くなるまで繰り返してから
次のステップへ進む。

### 4.5 震源の確定・収束判定

- 一定tick数（例: 直近5秒）以上、震源位置が候補移動しなくなった時点で「収束」とみなし、
  イベントに `estimatedEpicenter: { lat, lon, depthKm, originTime, errorLevel, confirmed }`
  を付与する。
- 検知点が極端に少ない間（例: 2点のみ）は精度が低いため、`confirmed: false` のまま
  参考表示に留める（記事の能登半島沖の例のように暴れるリスクがあるため）。

## 5. アプリへの統合ポイント

- `shakeDetection.ts` の `processTick()` が返すイベント配列の各要素に、上記推定結果を
  追加フィールドとして持たせる（App.jsx側の既存の `shakeEvents` 消費コードに影響を
  与えない形で拡張）。
- 推定は毎tick回すと重いため、**検知点数が変化したイベントのみ**再計算する
  （変化が無ければ前回の推定結果を使い回す）。
- 地図表示: 揺れ検知円（`shake-events-layer`）とは別レイヤーで、推定震源位置に
  マーカー（例: ×印やクロスヘア）を表示。`confirmed` の有無で見た目（実線/点線、
  色の濃淡など）を変える。

## 6. パラメータ初期値（要調整）

| パラメータ | 値 |
|---|---|
| 初期深さ | 10km |
| 発生時刻オフセット | 検知時刻 − 2秒 |
| 着未着法 適用条件 | 検知3秒以内 or 検知30点未満 |
| 着未着法 探索範囲 | 最大震央距離 + 30km |
| 収束判定 | 5秒間 候補移動なし |

## 7. スコープ外（フェーズ2以降）

- 振幅（最大PGV）・B-Δ法・主成分分析による震源方位など、検知時刻以外のデータを使った
  精度向上（気象庁の改良IPF法的アプローチ）。
- P波/S波の判別による走時の使い分け。
- 複数地震の同時発生判定（同一地震判定）。

## 8. 実装で判明した既知の限界(検証済み)

合成データによる動作検証で、以下を確認・対処済み:

- **反復移動が暴走するケースがあった**: 初期深さ(10km)が実際の深さと大きく異なり、
  かつ検知済み観測点が地理的に近接している(震央距離のバリエーションが乏しい)場合、
  候補を無限に遠ざけるほど誤差レベルが下がる退化解にはまり、震源が全く見当違いの
  方向へ飛んでいくことがあった。対策として、(1) 初期仮震源から一定距離
  (600km)以上離れた候補は採用しない安全弁、(2) 反復移動の前半ステップでも
  深さを大まかに補正できるようにする、の2点を実装に追加した。
- 対策後も、検知点数が少ない・観測点の配置に偏りがある間は、真の震源から
  数十〜150km程度ずれることがある(特に深さの精度は低い)。検知点数が増えるに
  つれて収束していく傾向は確認できた(検証: 40点程度の検知でおおよそ数km〜
  10km程度の誤差まで収束)。参考記事でも同様の不安定さ(能登半島沖の例で
  「明後日の方向」に飛んだ、深さは「ガバガバ」)が報告されており、この手法
  そのものの限界と考えられる。
- そのため、4.5節の「収束判定」と「検知点が少ない間はconfirmed: false」の
  方針は実装上も重要(=精度が低い推定を確定表示しないためのガード)。

## 9. 実装状況

- `shakeTestSimulation.ts`: P/S波速度定数を`export`し、`epicenterEstimation.ts`
  から流用できるようにした。
- `shakeDetection.ts`: イベントに観測点ごとの初回検知時刻(`detectionTimes`)を
  追加し、`processTick()`の戻り値に`detections`配列として公開するようにした。
  検知アルゴリズム自体への影響はない。
- `epicenterEstimation.ts`(新規): `estimateEpicenter()`(1回分の推定を行う
  純粋関数)と`EpicenterEstimator`(イベントごとに検知点数が変化した時だけ
  再計算するキャッシュラッパー)を実装。
- `App.jsx`: `epicenterEstimationEnabled`設定(デフォルトOFF、設定タブに
  トグルを追加、localStorageに永続化)、地図上に×印マーカーを表示する
  専用レイヤー(`epicenter-estimates-layer`)、tickごとの推定呼び出しを追加。
  地震検知(`shakeDetectionEnabled`)がONの間のみ動作する。

## 10. 揺れの広がり方・方向の取り込み(追加実装)

当初9節までの実装は検知時刻のみを使う設計だったが、追加で以下を実装し、
「揺れの広がり方(震度の減衰パターン)」「その方向」も震源推定に反映するようにした:

- **初期仮震源の変更**: 従来は「最初に検知した1点の位置」を初期仮震源にしていたが、
  検知済み観測点を震度で重み付けした重心(震度が高い観測点ほど震源に近いはず、
  という直感)に変更した。震度→重みへの変換は、`shakeTestSimulation.ts`の
  `calcPeakIntensity`(震度 = 2.68 + 1.72*log10(PGV))の逆関数を使っている
  (絶対値としての精度は求めず、観測点間の相対比較にのみ使用)。
- **誤差レベルへのペナルティ追加**: 候補震源から見た「震央距離の対数」と
  「震度」のピアソン相関係数を計算し、理想的な負の相関(遠いほど震度が低い)
  からのズレをペナルティとして加算する(`computeAmplitudeConsistencyPenalty`)。
  到達時刻の分散だけでは区別しにくい候補同士を、震度の広がり方の整合性で
  追加的に絞り込む。
- 上記に伴い、`shakeDetection.ts`の観測点ごとの検知記録に、検知時点の震度
  (`level`)も保持するようにした(`detections`配列の各要素に`level`を追加)。
  震度データが無い(古い形式の)呼び出しでも動作するようフォールバックしてある。

**検証結果**: 合成データで比較したところ、震度を使わない場合に不安定だった
ケース(検知20点で150km誤差)が、震度を使うことで1.4km程度まで改善した。
検知点数が少ない(3〜5点)早い段階でも、数km程度の誤差に収まるケースが
確認できている。ただし引き続き、検知点数が少ない・観測点配置に偏りがある
状況では誤差が大きくなりうるため、8節の限界・9節の`confirmed`判定方針は
そのまま有効。
